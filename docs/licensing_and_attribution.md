# Licensing, Provenance, and Legal Attribution Architecture

This document formalizes the legal licensing frameworks, data provenance chains, and downstream derivative dataset obligations governing the **India-Specific POI Conflation** research project and its constituent data sources: **OpenStreetMap (OSM)** and **Overture Maps Foundation Places**.

---

## 1. Upstream Data Licenses

### 1.1 OpenStreetMap (OSM)
* **Governing License:** [Open Database License (ODbL) 1.0](https://opendatacommons.org/licenses/odbl/1-0/)
* **Licensor:** OpenStreetMap Foundation (OSMF) and OpenStreetMap contributors
* **Attribution Notice:** `© OpenStreetMap contributors`
* **License Details:**
  * **Share-Alike (Clause 4.4):** Any *Derivative Database* that incorporates OSM data (or is derived from queries, geometries, or attributes extracted from OSM) must be licensed under ODbL 1.0 if published, distributed, or publicly conveyed.
  * **Attribution (Clause 4.3):** Any public display, user-facing map, or downstream dataset containing OSM features must credit OpenStreetMap and make it clear that the data is available under ODbL.
  * **Reverse Engineering & Notice (Clause 4.2):** Redistributed databases must include a copy of the ODbL or a machine-readable URI pointing to it.

### 1.2 Overture Maps Foundation Places
* **Governing License:** [Community Data License Agreement – Permissive, Version 2.0 (CDLA-Permissive-2.0)](https://cdla.dev/permissive-2-0/)
* **Licensor:** Overture Maps Foundation (Linux Foundation Joint Venture)
* **Attribution Notice:** `Data provided by Overture Maps Foundation under CDLA-Permissive-2.0`
* **License Details:**
  * **Permissive Redistribution:** Grants a worldwide, royalty-free, non-exclusive, sublicensable permission to use, reproduce, modify, display, distribute, and make available data without requiring downstream share-alike licensing.
  * **Upstream Data Provenance in Overture Places:**
    * Overture's Places theme synthesizes records from multiple foundational contributors, primarily **Meta** (Facebook Graph places data), **Microsoft Bing** (places and point entities), **Esri**, and community open data.
    * Each Overture record carries provenance metadata in `sources`, identifying the upstream contributor and timestamp of each ingested attribute.

## 2. Conflation and Derivative Database Obligations

### 2.1 The "Derivative Database" vs. "Collective Database" Distinction
The OpenStreetMap Foundation legal guidelines distinguish between:
1. **Collective Database (Independent / Horizontal Linking):** Two distinct databases distributed alongside one another where neither depends on the other to exist, linked externally (e.g., a foreign key lookup table mapping `osm_id` $\leftrightarrow$ `overture_id`).
2. **Derivative Database (Conflated / Unified Schema):** A database created by combining, enriching, harmonizing, or snapping geometries and attributes from OSM and an external source into a single unified record (e.g., our canonical POI schema enriched by OSM tags and Overture categories).

### 2.2 Conflation Legal Implications
Because the conflation pipeline in this project:
- Cross-references OSM nodes/ways with Overture point entities;
- Generates canonical composite entities that may inherit attributes (names, categories, phone numbers, localized vernacular scripts) from either or both sources;
- Evaluates spatial proximity and attribute similarity directly;

The resulting merged entity table (`canonical_pois.parquet` or conflated cluster outputs) qualifies as a **Derivative Database** under ODbL Section 4.4.

> [!IMPORTANT]
> **Share-Alike Implication:** Any consolidated or conflated dataset generated by this pipeline that contains OSM-derived geometries, names, or tags, if publicly released or shared, **must be licensed under ODbL 1.0** to comply with upstream OSM Share-Alike terms.

### 2.3 Compatibility of CDLA-Permissive-2.0 with ODbL 1.0
* CDLA-Permissive-2.0 explicitly permits data to be sublicensed or re-licensed under different terms (including copyleft or share-alike licenses such as ODbL 1.0), provided that the required attribution to Overture Maps Foundation and its upstream licensors is maintained.
* There is no legal conflict in placing a combined Overture + OSM conflation output under ODbL 1.0, provided both attribution notices are prominently preserved.

## 5. Data Handling and Git Hygiene

To guarantee complete compliance with intellectual property boundaries and repository storage limits:
1. **Raw data files (`*.pbf`, `*.parquet`, `*.geojson` caches) are strictly excluded from Git tracking** via `.gitignore`.
2. The repository contains only deterministic, reproducible data acquisition scripts (`acquire_osm.py`, `acquire_overture.py`, `acquire_boundary.py`) that fetch directly from authoritative upstream endpoints with cryptographic checksum verification and metadata logging.
3. Every data acquisition run generates an immutable `extraction_metadata.json` capturing timestamp, upstream release version, query bounding box, SHA-256 digest, record count, and license URI.
